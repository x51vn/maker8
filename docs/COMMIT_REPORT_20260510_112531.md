## Detailed Changes

- `src/maker8/config.py`: new `normalize_max_audio_channels: int = 2` field in `Settings`; default 2 restores stereo; set to 1 for legacy mono behaviour
- `src/maker8/pipeline/normalize.py`:
  - `_probe_audio_channels(path, timeout=10) -> int` — runs ffprobe `-select_streams a:0 -show_entries stream=channels -of csv=p=0`; returns 1 on any exception with a structured warning log
  - `NormalizeStage.__init__` gains `max_audio_channels: int = 2`; stored as `self._max_audio_channels`
  - `_normalize_audio` (static) gains `max_audio_channels: int = 2`; computes `target_channels = min(detected, max_audio_channels)`; replaces `-ac 1` with `-ac {target_channels}`; logs `normalize.audio_channels` with `detected`, `target`, `clamped`
  - Both call sites in `_normalize_asset` pass `self._max_audio_channels`
- `src/maker8/pipeline/orchestrator.py`: `NormalizeStage(proxy_max_short_edge=..., max_audio_channels=settings.normalize_max_audio_channels)`

## Change Content Summary

- **Behavior**: audio assets normalised to stereo WAV by default instead of always mono; channel count clamped to `min(detected, max_audio_channels)` so mono sources stay mono and surround is clamped to stereo
- **Config**: operator sets `NORMALIZE_MAX_AUDIO_CHANNELS=1` env var to restore legacy mono
- **Observability**: structured log event `normalize.audio_channels` added for every audio normalisation
- **Resilience**: ffprobe failures silently fall back to mono — job never fails due to probe error
- **Tests**: 7 tests covering all branches; 442/442 suite passing
